# tgcli 8.0 execution contract

User authorization on 2026-11-20 covers implementation of the remediation roadmap, breaking old contracts, SOL workers, updated skills, public 8.0.0 release and local installation. This supersedes the earlier audit-only boundaries of the roadmap. Live writes remain limited to controlled test resources; production contacts, bots and authorization must not be modified for verification.

## Decisions

1. Normal discovery and reads synchronize with Telegram within one bounded operation deadline. Explicit `--local` means cache-only throughout acquisition and enrichment, carries `source=local_cache`, and never authorizes absence/deletion inference. An unavailable optional remote field is null/unknown, not a fabricated zero.
2. A request for at most N matching rows succeeds when N are obtained or the authoritative source is exhausted. A native short page is not exhaustion. A filtered-empty page can have a continuation. `--all` means exhaustive within declared filters; hitting a safety bound makes it incomplete and nonzero. Native message IDs are not arithmetic cursors. Search consumes its API's returned continuation; history reuses real native IDs with overlap protection.
3. Keep TSV as the compact human read default. JSON is one parseable document per invocation, including multi-query search. JSONL is one versioned record per line. JSON message records use the rich export schema, version `8.0`, everywhere; remove the simple/rich switch. Do not add legacy adapters. Full exports are snapshots, not append-only journals.
4. JSON collection results expose rows and acquisition metadata (source, requested scope, complete/history exhaustion, termination reason and continuation where supported). `complete` describes source exhaustion, independently of whether the bounded request succeeded. JSONL/TSV/plain output keeps data on stdout and emits one machine-readable result summary on stderr when source/scope/completeness needs communicating; it must distinguish an exhausted empty result from cached or partial output. File export uses its verified manifest. Do not contaminate the JSONL message stream with control records consumed as messages by batch download.
5. All externally documented machine IDs are decimal strings, including file/topic IDs. Counts, offsets, sizes and timestamps expressed as Unix seconds remain numeric. Timestamp strings use ISO 8601 UTC with a `Z` or explicit `+00:00`; date-only boundaries mean UTC. All message formats sort chronologically by `(date, chat_id, message_id)`; query batches retain the query label and deterministic order.
6. Exit codes: 0 fulfilled request (including empty complete results and an intentionally bounded page); 1 operational failure; 2 invalid usage or input; 3 explicit partial result; 4 login required/revoked authorization; 5 deadline exceeded; 130 cancellation. Failures carry a useful classified explanation on stderr. Broken output pipes terminate promptly without printing an irrelevant stack trace. Help/version and input validation do not acquire Telegram sessions.
7. Common operations use one `--request-timeout` of 60 seconds (1..3600) spanning lock wait, auth/readiness, acquisition and enrichment. `--lock-timeout` may narrow the lock wait, never extend the total deadline. Bot workflows must report uncertain outcomes and must not automatically resend a possibly accepted mutation. Local transcription can use an explicit larger timeout. MCP keeps its documented bounded timeout and reports equivalent error classifications.
8. Context, get, links, stats, topics, comments, metrics and attachments use shared domain operations between CLI and MCP where both surfaces exist. Backend wrappers handle transport only; no second cursor/download/enrichment implementation. A normal command never asks the user to clear internal caches or retry a special sequence to receive current data.
9. Export defaults to complete current acquisition, validates scope/schema/checkpoints, upserts edits, derives deletions only from authoritative full scope, and commits data/manifest recoverably. Repeating an unchanged refresh preserves logical content/counts. Explicit bounded/local export is labeled and cannot update an authoritative cache. Remove redundant repair flags when the invariant becomes unconditional.
10. Install/update downloads to staging, verifies checksum/version and execution, then replaces atomically. Release gates run the packaged executable on each supported x64 OS. Generated notes, binary version and tag must match. Linux/macOS/Windows coverage must be observed, not inferred from a workflow file.

## Integration work

After the six domain lanes: a SOL CLI worker owns Program/Output/shared wire normalization and CLI handler adoption; a separate SOL worker owns MCP backend/schema parity using merged domain APIs; a SOL release worker owns CI, installer scripts, packaging gates and release docs; a SOL skill worker updates the source skill and explicitly selected relevant installed skills. Shared handler edits integrate sequentially. Review findings get behavioral regression tests and fixes before publication.

## Acceptance basis

All audit findings F01–F25 and hypotheses retain traceability in the remediation report. FLOW-01–FLOW-18 derive from discoverable usage sessions; synthetic fixtures are the oracle. The original incident is covered by cold/empty cache readiness, a short first page followed by newer messages, explicit disconnected state, no constant network health, and repeated reads/refresh after interruption. Fault injection must exercise real domain calls; helper-only tests cannot establish the production handler contract.

Unperformed live/device/client tests must be named explicitly. They cannot be reported as passed. Measurements may justify leaving the current single distribution unchanged; no daemon or additional cache is assumed.
