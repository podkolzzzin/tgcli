# tgcli 8 usage flows and acceptance fixtures

The local scan streamed 1,224 rollout files from the active and archived Codex session stores, including 881 zstd-compressed rollouts and 343 plain JSONL rollouts. The rollouts span 2025-12-30 through 2026-11-20. The legacy history sidecar contributed 897 prompt records, including 32 literal matches. It is an index of prompts and contributes zero additional rollouts to the totals.

There were 1,117 rollout text matches. Of those, 947 contained matches only in injected or structural context. The remaining 170 had a tool, user, assistant, or tgcli checkout signal. There were 81 command-bearing rollouts dated 2026-07-06 through 2026-11-20, with 1,116 structurally identified invocation-shaped tool calls. This includes 75 CLI command-bearing rollouts with 1,008 call records and 12 MCP command-bearing rollouts, with six using both transports. Counts include probes and setup. An invocation-shaped tool record can contain several invocations, a test, or a quoted command. Frequency in the tables is same-session co-occurrence, independent of command order or success.

CLI usage clustered around message reads (43 sessions), chat-scoped search (38), exports (33), chat discovery search (31), downloads (30), individual message inspection (28), chat listing (27), and context windows (23). Common historical flags include `--all` (40 sessions), `--include-links` (25), `--max-pages` (21), `--all-history` (19), `--server` (18), `--fail-incomplete` (18), and `--lock-timeout` (17). Those flags help locate the underlying jobs. Success in old logs has no authority over the v8 contract.

## Defaults to validate for v8

- Normal discovery and reads use current remote data. Cache access is explicit and observable. Success means the command fulfilled its stated scope, whether a few recent rows, a bounded search, or exhaustive history.
- Exact handles, chat/message IDs, and Telegram links should form a straightforward lookup path. Use typed or distinguishable identifiers with decimal string machine representations and UTC date values.
- Ordinary export verifies source scope and completeness by default. Reports can use a stable link and attachment model. Refresh should have clear idempotent snapshot semantics and should validate the existing scope before replacing files.
- Use one bounded operation deadline and explicit cancellation, with safe and bounded retries for reads. Expose session and connection state when a command cannot complete. A caller that asks for help or intentionally gets an empty complete result succeeds. Invalid, interrupted and partial operations are distinguishable from success.
- Keep machine-readable results parseable and use one documented ordering. An unsupported option or output format fails before I/O. A batch result identifies each item and any partial outcome.
- Treat the tests as synthetic contracts. Report research tasks never require replaying private content, accessing native account history, or mutating Telegram to confirm parser and transport behavior.
